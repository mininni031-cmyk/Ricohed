# 重力シフトと4面ゴールの設計（v2.6）

## 1. 座標系
- ゲームの判定は、すべて**部屋の座標（room-local）**で行います。
  - 部屋は原点を中心とする箱です：x, y ∈ [−11, 11]、z ∈ [−9, 9]。
  - z軸が回転軸です。z方向の2面はガラスの壁で、床やゴールにはなりません。
- 部屋の座標で見ると、面・ゴール・パネルは**動きません**。変わるのは**重力ベクトル**だけです。
- 表示するときは、部屋のグループ（`ArenaScene.room`）を z軸のまわりに `angle` だけ回し、固定された観客席の中に置きます。
- **正準座標（canonical）**：最後に回転が終わったときの向きに合わせて、部屋の座標を回したもの。
  - 床は y = −L、CYANのゴールは −x、PINKのゴールは +x です。
  - CPUの思考、スポーン位置、ハーフラインの向きは正準座標で書いてあるので、どの向きのときも同じ考え方で動きます。
  - 変換は `gravity.localFromCanon()` / `canonFromLocal()` で行います。

## 2. ArenaGravitySystem（`src/gravity.js`）
- 状態：`k`（回転が終わった回数）、`clock`（試合時間に連動）、`phase`（stable / warning / rotating / settle）、`angle`。
- 角度：`angle = −90°·k − 90°·smootherstep(t / 6)`。回転中だけ第2項が増えます。smootherstep は始めと終わりで速度も加速度も0です。
- 上方向：`up = (sin angle, cos angle, 0)`。重力は `−up × 15.2 m/s²` です（**強さは常に一定**）。
- 時間の流れ（周期30秒）：

```
 0 ───────────── 28 ─── 30 ──────────── 36 ─ 37 ──────────── 58 ─── 60 …
     stable        warning   rotating(6s)   settle    stable      warning
                   「ARENA SHIFT IN 2 → 1」  「GRAVITY SHIFT」 「NEW FLOOR」
```

- 発行するイベント：`GRAVITY_SHIFT_WARNING`、`GRAVITY_SHIFT_COUNT {sec}`、`GRAVITY_SHIFT_STARTED {k}`、`GRAVITY_SHIFT_COMPLETED {k}`。
- 時計は試合時間と一緒に進みます。ポーズ中は止まります。ゴールのお祝い中に回転していた場合は、回転を最後まで進め、試合時計も同じだけ進めます。
- `endAt`（試合時間）以降に始まるシフトは予告しません。

## 3. 何が「床」か
- 面の法線 n と上方向 u について、`n·u ≥ 0.695`（約46°以内）なら、その面は床です。
- 回転中に今の床の傾きがこれを超えると、プレイヤーは床から離れて（`slidOff`）、落下・滑走します。新しい床に着くと空中アクションが回復します（`slidOff` があるので、短い滞空でも回復します）。
- 壁の条件は `|n·u| < 0.5` です。ウォールキックは、今の重力に対して壁である面でだけ発動します。

## 4. 4面ゴール（`src/goals.js`）
床になりうる4面（±x, ±y）それぞれに口を2つ配置しています。口は「隣の面寄り」で、中心は `n·L + s·(L − 2.0)` です（n＝その面、s＝隣の面）。どの面が床になっても、その床から2.0 mの高さに口があります。

有効な2口 ＝ 「今の床の左右の面（正準座標の ∓x の面）にある、床寄りの口」：

| k（回転回数 mod 4） | 床（部屋の座標） | CYANの口（左） | PINKの口（右） |
|---|---|---|---|
| 0 | −y | −x \| −y | +x \| −y |
| 1 | +x | −y \| +x | +y \| +x |
| 2 | +y | +x \| +y | −x \| +y |
| 3 | −x | +y \| −x | −y \| −x |

（表記は「面 \| 寄せる隣の面」。テスト#20で4つの向きすべてを確認：CYANは常に世界の左（world x = −1）、PINKは常に右（+1）、どちらも床から2.0 m）

- 回転中も `k` は変わらないので、**前の2口が有効のまま**です。`GRAVITY_SHIFT_COMPLETED` で `k` が1増え、有効な口・キーパー・シャッターの表示が切り替わります。
- 得点の条件：有効な口の面の手前 `L − r`（ディスクの前の縁が面に届く位置）を、外向きに越えたとき、口の中心から1.45 m以内なら得点です。
  - 1.45〜(1.59 + 0.14 + r) m のときは、リングに当たって反射します。
  - 有効でない口は、ただの面として反射します。

## 5. キーパー（`src/keeper.js`）
- 自分のチームの有効な口に、口の法線・寄せる方向から作った座標系で立ちます。
  - 上 ＝ −s
  - 前 ＝ −n
  - 横 ＝ 上 × 前（常に ±z）
- 横方向の位置は `sin(試合時間)` だけで決まり、ディスクには反応しません。
- 当たり判定：Yスタンスのポーズを付けた骨格から測った6つのカプセル（両腕・両脚・胴・頭）×1.25倍。描画と同じポーズなので、見た目と判定は一致します（テスト#22で関節が判定の中に入ることを確認）。
- 口が切り替わると新しい床に立ち直し、0.3秒の登場アニメーションを行います。その間はセーブしません。

## 6. ハーフライン
- ハーフラインは、中心を通り、正準座標の x軸に垂直な面です。部屋の座標では `teamDir` に垂直な面になります。
- 回転中は無効です。回転が終わったときに、自分の側（`pos·teamDir ≥ 0.4`）にいない人は、自陣のスポーン位置（z座標は保つ）へワープします（`PLAYER_WARPED`）。
- 現状の偏り：右回りの回転では、部屋の中の人が「新しい床とCYAN側の壁の角」へ集まるので、PINK側がワープしやすくなります（[ROADMAP](ROADMAP.md)に記載）。

## 7. カメラ
- プレイヤーの視点（yaw / pitch）は**世界の座標**で持っています。部屋が回っても水平線は水平のままで、部屋が自分の周りを回るように見えます。
- 照準の方向は、`gravity.toRoomDir(worldForward)` で部屋の座標に直します。
- 酔い軽減：回転中は画面の周辺を暗くし、視野角を最大6°狭めます（sinカーブ）。

## 8. 端のケースと決めたこと
| ケース | 扱い |
|---|---|
| 回転中のゴール | 前のゴールで得点になる。お祝い中に回転を最後まで進め、それから次のプレーへ |
| 回転中にディスクを持っている | そのまま持てる。持ち時間も進む |
| 回転中のキャッチ | 同じルールで可能（バランス検証で20回中20回成功） |
| 試合終了と同時のシフト | 予告しない。HUDに「FINAL STAGE」 |
| 回転で角に挟まる | カプセルは毎ステップ、最後に6面から押し出す（3分間の試合で食い込み0） |
